# InferScale-X V2 — single-A100 edition

A reproducible, evidence-first LLM inference reference platform. Everything that can run
on **one NVIDIA A100 in Google Colab** is implemented and produces measurements; everything
that needs a cluster is shipped as a clearly labelled reference design. No number in this
repo is typed by hand: results are generated by scripts, and résumé claims are rendered
from those result files (`docs/CLAIMS.md`).

> **JD coverage:** `docs/jd-coverage.md` maps every NVIDIA JD keyword to its deliverable, separating
> what the code implements (19/22) from what is design-only (Triton Inference Server, fabrics, Grove)
> and from what your result files actually prove (starts at 0, updated by `make results`).
>
> **Status when you unzip this:** the code is complete and the CPU test suite passes
> (gateway, routing, admission, agents, sandbox, retrieval eval, KV simulator, failure injection
> on mock backends, and both Triton kernels checked on CPU through the Triton interpreter). **No GPU results exist yet** — you produce them by running the Colab
> notebooks. `docs/READINESS.md` starts at 1/12 (only "customer-readiness docs exist" can pass
> without a GPU) and fills in from evidence only.

## What runs on one A100 vs. what doesn't

| Pillar | Implemented and measured on Colab A100 | Honest limitation |
|---|---|---|
| 1 Production foundation | OpenAI-compatible FastAPI gateway: API-key auth (hashed), multi-tenant rate limits, admission control (429/503 + Retry-After), SSE streaming proxy, retries/failover, health checks, Prometheus metrics, JSON logs, optional OTel; vLLM backend. **Real Kubernetes on kind** (Mac or CI): anti-affinity scheduling, pod-kill recovery under load, HPA scale-up, Calico NetworkPolicy. docker-compose stack with Prometheus + Grafana | kind runs CPU mock replicas — GPU scheduling is reference-only |
| 2 Distributed inference | Routing policies (round-robin / least-outstanding / **KV-aware prefix affinity**) across 2 vLLM replicas; prefill→decode interference measured; emulated disaggregation; **attempts** at vLLM NIXL/P2P connectors and NVIDIA Dynamo with logged outcomes | 2 replicas share one GPU; no real cross-GPU KV hop. Dynamo/NIXL results are "attempted", not claimed |
| 3 GPU optimisation | Custom **Triton** kernels: FlashAttention-style attention forward (vs PyTorch SDPA) and fused add+RMSNorm, both CPU-verifiable via the Triton interpreter; quantisation BF16 vs AWQ-INT4 vs GPTQ-INT8 vs FP8-weight-only; speculative decoding (HF lossless check + vLLM draft/n-gram); vLLM vs SGLang vs TRT-LLM (separate runtimes) | A100 has no FP8 tensor cores; Nsight Systems usually unavailable on Colab (torch.profiler trace instead) |
| 4 KV-cache engineering | Prefix caching on/off, HBM-pressure sweep, **cross-tenant cache side-channel demonstrated and closed** with per-tenant `cache_salt`; **real CPU-DRAM KV tier** (vLLM offloading / LMCache) with HBM capped below the working set, plus a localhost remote tier; KV transfer bandwidth + cost model; eviction-policy simulator | Remote tier runs on localhost |
| 5 Secure agents | BM25 RAG, tenant-scoped SQLite memory, sandboxed Python (rlimits + audit hooks), versioned & hash-locked skills, policy engine with taint tracking, hash-chained audit log, eval vs RAG baseline, prompt-injection & unauthorised-tool suites; **retrieval eval** (32 labelled queries: hit@1, recall@k, MRR, nDCG; BM25 vs dense vs hybrid) | Sandbox is defence-in-depth, not gVisor/Firecracker (documented in threat model) |
| 6 Model customisation | SFT, DPO (and SFT→DPO), GRPO (heuristic reward) vs RLVR (verifiable reward) with LoRA on Qwen2.5-0.5B; dataset lineage + leakage check; held-out eval + serving-token cost | Small model, synthetic verifiable task: in-distribution results only |
| 7 Partner architecture | Deployment guide, ADRs, threat model, runbooks, capacity/cost model driven by measured throughput (large-cluster rows labelled EXTRAPOLATED); live public demo endpoint from Colab (fresh key per session) | No 10,000-GPU claims, ever |
| Open source | MIT licence, CONTRIBUTING/SECURITY, issue + PR templates, CITATION, generated `docs/RESULTS.md`, upstream-contribution tracker, one-command `publish_repo.sh` | The upstream contributions themselves are yours to make |

## Quick start

**Laptop / CI (no GPU):**
```bash
pip install -r requirements/dev.txt
python -m pytest            # all CPU tests pass; 8 live tests skip without a GPU server
make demo                   # gateway + 2 mock backends + a load test
```

**Mac (deploy + Kubernetes):** see `docs/RUNNING_ON_MAC.md` — `make compose-up` (gateway + replicas +
Prometheus + Grafana) and `make k8s` (3-node kind cluster with real scheduling/recovery/HPA/NetworkPolicy evidence).

**Colab A100:** upload the zip, open `notebooks/01_core_platform_A100.ipynb`, set runtime to
A100, run top to bottom (≈3–5 h). Then `02_model_customization_A100.ipynb` (fresh runtime,
≈2 h) and optionally `03_alt_engines_and_dynamo.ipynb`. Full guide: `docs/RUNNING_ON_COLAB.md`.
Or from a terminal cell: `bash scripts/colab_setup.sh core && bash scripts/run_all_core.sh 3`.

## Evidence rules (enforced by `scripts/evidence_report.py`)
1. Every experiment records env (GPU, driver, CUDA, package versions), workload, raw per-request JSONL, and repeats with mean/std/95% CI.
2. Comparisons report a verdict (`improved` / `regressed` / `no_significant_difference`) — losses are kept and listed as negative-result candidates.
3. Claims in `docs/claims.yaml` are rendered with real numbers or printed as **NO EVIDENCE – do not use**.
4. Measured, emulated, simulated and extrapolated results are labelled as such in every report.
